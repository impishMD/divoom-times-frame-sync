# Divoom Times Frame Sync

[English](README.md) | **Русский**

Синхронизация **публичных фотоальбомов** Google Photos, iCloud Photos, Immich, OneDrive и Яндекс Диска с фоторамкой **Divoom Times Frame**.

Добавьте ссылки на альбомы, выберите альбомы назначения на рамке — сервис будет автоматически поддерживать их состав. Альбомы из разных сервисов можно объединить в одно слайд-шоу или синхронизировать в отдельные альбомы рамки.

Фотографии сохраняются в штатные альбомы рамки и показываются **автономно**. Сервис нужен для переноса изменений; после его остановки показ продолжается.

## Возможности

- Синхронизация всех настроенных публичных альбомов за один запуск, включая несколько альбомов одного сервиса.
- Загрузка новых фотографий и поддерживаемых видео по локальной сети.
- Объединение источников с одинаковым альбомом назначения.
- Исключение исчезнувших элементов из альбома рамки или их сохранение — в зависимости от режима.
- Удаление временных локальных файлов после подтверждённой загрузки и хранение небольшого журнала синхронизации между запусками.

## Поддерживаемые публичные альбомы

Сервис использует **ссылки общего доступа к альбомам**, которые открываются без входа в аккаунт источника. Для Immich также поддерживаются ссылки с паролем. Включите публичный доступ или доступ по ссылке для каждого альбома, который хотите синхронизировать.

| Сервис | Формат ссылки на альбом | Фото | Видео |
| --- | --- | --- | --- |
| Google Photos | `photos.app.goo.gl/...` или `photos.google.com/share/...` | Да | Да |
| iCloud Photos | `photos.icloud.com/shared/album/...` | Да | Пока нет |
| Immich | `<ваш-сервер>/share/...`, в том числе с паролем | Да | Да |
| OneDrive | `1drv.ms/a/...` из личного аккаунта | Да | Пока нет |
| Яндекс Диск | `disk.yandex.ru/a/...` или `disk.yandex.com/a/...` | Да | Пока нет |

Для чтения этих альбомов не нужны вход в аккаунты, настройка OAuth или автоматизация браузера. Каждая ссылка предоставляет доступ к своему альбому: храните реальные ссылки и пароли в локальных файлах конфигурации.

## Начало работы

### 1. Подготовьте рамку и конфигурацию

Понадобятся Divoom Times Frame, доступная по локальной сети, её IP-адрес и локальный токен, а также хотя бы одна ссылка на публичный альбом. Заранее создайте альбомы назначения в приложении Divoom: их имена должны точно совпадать с конфигурацией.

Скачайте проект и скопируйте примеры конфигурации:

```sh
git clone https://github.com/impishMD/divoom-times-frame-sync.git
cd divoom-times-frame-sync
cp .env.example .env
cp sources.example.toml sources.toml
chmod 600 .env sources.toml
```

В `.env` укажите подключение к рамке и ссылки, которые будете использовать. Замените IP-адрес, токен и ссылки из примера своими:

```dotenv
DIVOOM_HOST=192.168.1.100
DIVOOM_TOKEN=123456
DIVOOM_ALBUM=Photos
SOURCES_FILE=./sources.toml
SYNC_MODE=mirror
SYNC_INTERVAL=300

GOOGLE_PHOTOS_SHARE_URL=https://photos.app.goo.gl/your-album
ICLOUD_SHARE_URL=https://photos.icloud.com/shared/album/your-album
IMMICH_SHARE_URL=https://immich.example.com/share/your-key
IMMICH_SHARE_PASSWORD=
ONEDRIVE_SHARE_URL=https://1drv.ms/a/your-album
YANDEX_DISK_SHARE_URL=https://disk.yandex.ru/a/your-album
```

В `sources.toml` оставьте только нужные источники. Пример содержит все пять сервисов; заполнить ссылки нужно только для оставленных секций. Например, эти два источника пополняют один альбом рамки:

```toml
[[sources]]
id = "google-family"
provider = "google_photos"
url_env = "GOOGLE_PHOTOS_SHARE_URL"
target_album = "Photos"

[[sources]]
id = "icloud-family"
provider = "icloud"
url_env = "ICLOUD_SHARE_URL"
target_album = "Photos"
```

Для дополнительных альбомов добавьте секции `[[sources]]`, в том числе с повторяющимся сервисом. Каждому источнику нужны уникальный постоянный `id` и своя ссылка. Одинаковый `target_album` объединяет источники; разные значения направляют их в отдельные альбомы рамки. Полный формат описан в [настройке источников](docs/sources.md).

### 2. Запустите сервис

Выберите Docker Compose или локальную установку Python. Оба способа используют одинаковые `.env`, `sources.toml` и каталог `data/`.

#### Docker Compose

Готовые образы доступны для **Linux amd64 и arm64**:

- Docker Hub: `impishmd/divoom-times-frame-sync`
- GitHub Container Registry: `ghcr.io/impishmd/divoom-times-frame-sync`

По умолчанию Compose использует последнюю стабильную версию из Docker Hub:

```sh
docker compose pull
docker compose up -d --no-build
docker compose logs -f
```

Чтобы закрепить версию или использовать GHCR, задайте `TFS_IMAGE` в `.env`, например `TFS_IMAGE=ghcr.io/impishmd/divoom-times-frame-sync:v0.5.0`. У стабильных релизов есть тег версии и `latest`, у предварительных — только тег версии. Для обновления выполните `docker compose pull && docker compose up -d --no-build`. Для сборки из локальных исходников используйте `docker compose up -d --build --pull never`.

Контейнер включает FFmpeg для преобразования видео. `sources.toml` подключается только для чтения, состояние синхронизации сохраняется в `data/`. Контейнеру нужен исходящий доступ к сервисам альбомов и локальному API рамки, обычно на порту `9000`. Публиковать входящие порты не требуется.

#### Python на macOS или Linux

Требуется Python 3.11+. Из каталога проекта:

```sh
python3 -m venv .venv
.venv/bin/python -m pip install .

# Посмотреть источники и состояние рамки:
.venv/bin/tfs status

# Синхронизировать все альбомы один раз и включить показ:
.venv/bin/tfs sync

# Поддерживать синхронизацию автоматически:
.venv/bin/tfs run
```

Для видео дополнительно установите FFmpeg с `ffprobe` и кодеком `libx264`: `brew install ffmpeg` на macOS или `sudo apt-get install ffmpeg` на Debian/Ubuntu. Для синхронизации только фотографий FFmpeg не нужен.

Команда запуска — `tfs`. Ctrl+C завершает сервис, сохраняя показ на рамке. `SYNC_INTERVAL` задаёт паузу между циклами синхронизации, а не интервал смены кадров.

## Режимы синхронизации

| Режим | Новые элементы | Элементы, исчезнувшие из исходных альбомов |
| --- | --- | --- |
| `mirror` — по умолчанию | Добавляются в альбом рамки | Исключаются из этого альбома, если отслеживаются сервисом |
| `append` | Добавляются в альбом рамки | Сохраняются, включая прежние версии изменённых элементов |

Укажите `SYNC_MODE` в `.env` или переопределите режим при запуске:

```sh
.venv/bin/tfs run --sync-mode mirror
.venv/bin/tfs run --sync-mode append
```

**Удаление означает исключение элемента из альбома назначения.** Файл остаётся в памяти рамки и во «Все фото»; эта операция не освобождает место на устройстве. Другие альбомы и добавленные вручную элементы сохраняются. Сервис не меняет исходные альбомы и облачные оригиналы.

Каждый альбом назначения сверяется с объединённым составом всех его источников. Если один источник не удалось прочитать полностью, обновление этой цели пропускается в текущем цикле. Старые элементы исключаются только после подтверждения всех текущих файлов на рамке. Другие альбомы назначения могут синхронизироваться независимо.

## Показ и форматы медиа

Рамка показывает один альбом за раз. Для общего слайд-шоу укажите одинаковый `target_album` у всех источников. Сервис предпочитает альбом из `DIVOOM_ALBUM`, затем первый непустой альбом назначения в порядке конфигурации.

`sync` выбирает альбом после загрузки. `run` выбирает его после первого успешного непустого цикла; последующие обновления не переключают экран. Интервал смены кадров, порядок, эффекты, автозапуск видео и громкость задаются в приложении Divoom.

Фотографии подготавливаются под 800×1280 и загружаются как WebP. `IMAGE_FIT=contain` сохраняет изображение целиком с полями; `cover` заполняет экран с обрезкой.

Синхронизация видео доступна для альбомов Google Photos и Immich. Ролики преобразуются локально в MP4 с видео H.264 и звуком AAC при наличии, с размером 800×1280 и частотой 30 кадров/с. Поворот учитывается, `IMAGE_FIT` управляет кадрированием, длительность сохраняется полностью. Каждый ролик загружается с обложкой WebP и подчиняется тем же правилам синхронизации, что и фотографии. Для автоматического воспроизведения включите автозапуск видео на рамке.

Google Photos отдаёт перекодированную версию видео по ссылке публичного альбома. Недавно загруженному ролику может понадобиться время на обработку у Google. Если видео ещё недоступно или скачивание прервалось, сервис повторит попытку в следующем цикле и сохранит существующие элементы альбома.

## Локальное хранение

Обычные `sync` и `run` обрабатывают медиа по одному. **Временная локальная копия удаляется после проверки файла, принадлежности альбому и сохранения журнала.** Постоянное место для копии всех ваших альбомов не требуется.

Для фото нужно временное место под подготовленное изображение. Для преобразования видео — под скачанный ролик, готовый MP4 и обложку. После успешной загрузки в `data/` остаются небольшие метаданные: ID источников, ревизии, контрольные суммы и сведения об отслеживаемых записях рамки.

Неизменённые элементы повторно из источника не скачиваются. Проверка целостности всё равно читает файлы обратно с рамки по локальной сети, поэтому большие видео могут проверяться долго. При прерванной загрузке подготовленные файлы остаются для повторной попытки; устаревшие временные версии очищаются после успешного обновления списка источника.

**Сохраняйте `data/` между запусками и перезапусками контейнера.** Без него совпадающие файлы можно найти повторно, но принадлежность уже исчезнувших из источников записей восстановить не получится. Повторная обработка с другими настройками или кодеками также может создать отдельную копию. Подробнее — в [описании хранения и восстановления](docs/storage.md).

## Настройки

| Переменная | Назначение | По умолчанию |
| --- | --- | --- |
| `SOURCES_FILE` | TOML со списком публичных исходных альбомов | В примере задан `./sources.toml` |
| `DIVOOM_HOST` | IP-адрес или имя рамки | Обязательное значение |
| `DIVOOM_PORT` | Порт локального API | `9000` |
| `DIVOOM_TOKEN` | Числовой локальный токен устройства | Пусто |
| `DIVOOM_ALBUM` | Альбом назначения по умолчанию и предпочтительный для показа | `Photos` |
| `DIVOOM_USER_ID` | Необязательный ID отправителя | `0` |
| `SYNC_INTERVAL` | Пауза между циклами синхронизации в секундах | `300` |
| `SYNC_MODE` | `mirror` или `append` | `mirror` |
| `IMAGE_FIT` | `contain` или `cover`, для фото и видео | `contain` |
| `DATA_DIR` | Постоянное состояние и временные медиафайлы | `./data` |

Ссылки на альбомы указываются в `sources.toml` через `url_env` либо напрямую в `url`. Для ссылки Immich с паролем используйте `password_env` или `password`. Имена переменных окружения можно выбирать отдельно для каждого источника, подключая несколько альбомов одного сервиса.

Глобальные параметры `--env-file` и `--sources-file` ставятся перед командой:

```sh
.venv/bin/tfs --env-file .env --sources-file sources.toml sync
```

После изменения конфигурации перезапустите сервис. Для Compose используйте `docker compose up -d --no-build --force-recreate`.

## Дополнительные команды

| Команда | Действие |
| --- | --- |
| `.venv/bin/tfs status` | Прочитать состояние источников и альбомов рамки |
| `.venv/bin/tfs sync --dry-run` | Прочитать статус без изменений на рамке; список будущих удалений не рассчитывается |
| `.venv/bin/tfs snapshot` | Сохранить экран в `data/snapshot.webp` |
| `.venv/bin/tfs restore` | Выбрать ранее активный экран рамки |
| `.venv/bin/tfs cache` | Подготовить все медиа заранее и оставить локально до синхронизации |

`cache` — необязательная команда предварительного скачивания: она может занять место под всю подготовленную коллекцию. Для обычной работы она не нужна. Пути выше приведены для `DATA_DIR` по умолчанию.

## Текущие ограничения

- Источники должны открываться по поддерживаемым публичным ссылкам на альбомы. Закрытые библиотеки аккаунтов не поддерживаются.
- Видео из iCloud Photos, OneDrive и Яндекс Диска пока пропускаются. Live Photo из iCloud передаются как неподвижные изображения.
- Старые ссылки iCloud `sharedalbum/#...`, публичные папки Яндекс Диска и OneDrive, а также OneDrive for Business/SharePoint не поддерживаются.
- Протоколы публичных просмотрщиков могут меняться. Совместимость локального API рамки зависит от прошивки.
