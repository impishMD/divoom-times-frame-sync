# Несколько альбомов и сервисов

Один запуск `sync` или один цикл `run` обрабатывает **все** секции `[[sources]]`. Можно повторять один сервис сколько угодно раз, например подключить три альбома Immich и два Google Photos. Это список выбранных общих альбомов, а не автоматический доступ ко всей библиотеке аккаунта.

## Настройка

```sh
cp sources.example.toml sources.toml
chmod 600 sources.toml
```

В `.env`:

```dotenv
SOURCES_FILE=./sources.toml
IMMICH_SHARE_URL=https://immich.example.com/share/your-key
IMMICH_SHARE_PASSWORD=
GOOGLE_PHOTOS_SHARE_URL=https://photos.app.goo.gl/your-album
ICLOUD_SHARE_URL=https://photos.icloud.com/shared/album/your-album
YANDEX_DISK_SHARE_URL=https://disk.yandex.ru/a/your-album
ONEDRIVE_SHARE_URL=https://1drv.ms/a/your-album
```

Секреты можно хранить в `.env` и ссылаться на них из TOML:

```toml
[[sources]]
id = "immich-family"
provider = "immich"
url_env = "IMMICH_SHARE_URL"
password_env = "IMMICH_SHARE_PASSWORD"
target_album = "Family"

[[sources]]
id = "google-family"
provider = "google_photos"
url_env = "GOOGLE_PHOTOS_SHARE_URL"
target_album = "Family"

[[sources]]
id = "icloud-holidays"
provider = "icloud"
url_env = "ICLOUD_SHARE_URL"
target_album = "Holidays"
```

В этом примере `Family` получает объединение двух исходных альбомов, а `Holidays` — фотографии iCloud. Обычные альбомы `Family` и `Holidays` нужно заранее создать в приложении Divoom. Имена должны совпадать точно, а одинаковых имён на рамке быть не должно. Автоматическое создание альбомов в этой версии не реализовано.

Для новых сервисов добавьте секции (один сервис можно повторять с разными `id`):

```toml
[[sources]]
id = "yandex-family"
provider = "yandex_disk"
url_env = "YANDEX_DISK_SHARE_URL"
target_album = "Family"

[[sources]]
id = "onedrive-family"
provider = "onedrive"
url_env = "ONEDRIVE_SHARE_URL"
target_album = "Family"
```

Яндекс Диск поддерживает публичные фотоальбомы `disk.yandex.ru/a/...` и `disk.yandex.com/a/...`, OneDrive — публичные фотоальбомы личного аккаунта по ссылке `1drv.ms/a/...`. Публичные папки Яндекс Диска `/d/`, папки OneDrive и OneDrive for Business/SharePoint пока не реализованы. Пароль и вход в аккаунт для этих источников не поддерживаются; ссылка должна открываться анонимно. Браузерные зависимости устанавливать не нужно.

| Поле | Назначение |
| --- | --- |
| `id` | Уникальное без учёта регистра стабильное имя источника, до 64 символов: буквы, цифры, `-`, `_`. Не используйте название удалённого альбома как автоматически меняющийся ID |
| `provider` | `immich`, `google_photos`, `icloud`, `yandex_disk` или `onedrive` |
| `url` / `url_env` | Сама общая ссылка или имя переменной окружения с ней; указать ровно один вариант |
| `password` / `password_env` | Необязательный пароль Immich или имя переменной окружения с ним |
| `target_album` | Точное имя альбома рамки; если не задано, используется `DIVOOM_ALBUM` |

Общая ссылка сама предоставляет доступ к фотографиям. Реальные ссылки, пароли и временные токены не записываются в логи. `sources.toml`, `sources.local*.toml`, `.env` и `data/` исключены из Git и Docker build context. Если используете другое имя приватного файла, добавьте его в исключения самостоятельно.

```sh
# Все источники, один запуск:
.venv/bin/tfs sync

# Все источники каждые SYNC_INTERVAL секунд:
.venv/bin/tfs run

# Другой список источников; глобальный аргумент стоит перед командой:
.venv/bin/tfs --sources-file sources.local-family.toml sync

# Только чтение списка альбомов и состояния рамки:
.venv/bin/tfs sync --dry-run
```

`--sources-file` имеет приоритет над `SOURCES_FILE`. Файл и окружение читаются при запуске; после изменения списка перезапустите `run`. Если `SOURCES_FILE` не задан, продолжает работать прежняя конфигурация одного альбома через `IMMICH_SHARE_URL`.

## Объединение и удаление

Источники группируются по `target_album`. Сначала каждый провайдер получает полный список и сохраняет метаданные. Затем для каждого целевого альбома строится объединённый набор. Новые фотографии скачиваются и загружаются по одной; после подтверждения на рамке локальная копия удаляется.

В `mirror` удаляются только ранее отслеживаемые записи, отсутствующие во всём объединённом наборе. Если одинаковые подготовленные WebP-байты встречаются в двух источниках, файл на рамке один; исчезновение одного из источников фотографии его не удаляет. Визуально одинаковые снимки из разных сервисов могут иметь разное сжатие и дать разные байты — сравнения «на глаз» здесь нет.

Ошибка получения списка, неполная страница или недоступная общая ссылка блокирует **всё обновление соответствующего целевого альбома** до начала загрузок. Ошибка скачивания изображения во время переноса останавливает эту цель; уже добавленные фото могут остаться, но удаление старых не начинается. Остальные целевые альбомы продолжают синхронизироваться. Старый кэш не используется как доказательство актуального состояния недоступного источника. Разовая команда возвращает ненулевой код при любой ошибке, даже если остальные альбомы успешно обновились; `run` повторяет попытку в следующем цикле.

При удалении секции из конфигурации её фотографии перестают входить в объединение: в `mirror` ранее отслеживаемые фото удалятся из общего целевого альбома, если в него всё ещё направлены другие источники. В `append` останутся. Если целевой альбом полностью исчез из конфигурации, программа больше не обращается к нему и автоматически его не очищает. Перенос источника в другой целевой альбом следует тем же правилам. Исходные облачные альбомы программа только читает.

Удаление означает исключение из целевого альбома через `Photo/RemovePhotoFromAlbum`: запись в «Все фото» и файл в памяти рамки остаются. Фотографии, добавленные вручную, сохраняются. Подробности — [sync-modes.md](sync-modes.md).

## Автономное воспроизведение

На рамку загружаются все целевые альбомы, но активным штатным альбомом может быть только один. При `sync` и первом успешном цикле `run` выбирается непустой альбом `DIVOOM_ALBUM`, если он есть среди целей, иначе первый успешно синхронизированный непустой альбом в порядке TOML. Последующие циклы `run` не переключают экран.

Для единого автономного слайд-шоу всех фотографий укажите один `target_album` у всех источников. При отдельных целях переключение между альбомами задаётся средствами Divoom. Остановка синхронизатора оставляет фотографии и штатный показ на рамке.

## Кэш и переход со старой версии

- `data/sources/<id>/manifest.json` — постоянные метаданные источника; `photos/` и `videos/` — временные изображения и ролики до подтверждённого переноса. Удалённые ID хешируются для безопасных имён файлов; одинаковые ID разных сервисов не смешиваются.
- `data/targets/<hash>/manifest.json` — объединённый набор одного целевого альбома с ID исходных фотографий.
- `data/targets/<hash>/device-state.json` — журнал владения записями рамки для этого целевого альбома, с проверкой физического `DeviceId`, альбома, адреса и путей файлов.
- Корневой `data/device-state.json` сохраняет предыдущий экран для `restore` и журнал старой одиночной конфигурации.

При первом переходе на список источников старый журнал импортируется только при совпадении Immich-альбома, физической рамки и целевого альбома. Уже загруженные фотографии обнаруживаются и проверяются на рамке, повторно отправлять их не требуется. Существующие временные файлы источников удаляются после подтверждения на рамке. Манифесты сохраняют контрольные суммы для последующих циклов. Сохраняйте **манифесты и журналы в `data/`** между запусками. [Подробности хранения и восстановления](storage.md). Один корневой файловый lock не позволяет двум процессам с тем же `DATA_DIR` менять рамку одновременно.

Включённый `compose.yaml` предназначен для списка источников: он монтирует `sources.toml` только для чтения и `data/` для постоянного хранения. Для одного Immich-альбома оставьте в TOML одну секцию. Сначала подготовьте TOML и `.env`, затем выполните `docker compose up -d --build`.

## Добавление нового сервиса

Контракт находится в `src/timesframesync/source.py`:

1. `album() -> Album` возвращает стабильный ID альбома, название, **полный** список `Asset(id, revision, name, kind="photo")` и количество пропущенных видео. При ошибке или неполном ответе — `SyncError`, а не пустой список.
2. `preview(asset_id) -> bytes` возвращает декодируемое изображение для элемента последнего списка. Временные URL можно хранить в объекте провайдера; они не входят в манифест. Ревизия должна отражать изменение изображения и не меняться только из-за обновления подписи URL.
3. Для видео верните `kind="video"` и реализуйте `download_video(asset_id, destination: Path) -> None`: полностью скачайте ролик частями в указанный файл или поднимите `SyncError`. Сейчас это реализовано у Google Photos и Immich. `Album.photos` исторически называется так, но содержит оба вида медиа; `photo_count` и `video_count` дают отдельные счётчики. Провайдеры без поддержки видео продолжают учитывать их в `skipped`.
4. Добавьте провайдер и проверку URL в `sources_config.py`, фабрику в `providers/__init__.py`, тесты пагинации, пустого альбома, ошибок и отсутствия секретов в сообщениях.

Логику объединения, кэша, загрузки и удаления на рамке менять не нужно. Особенности нынешних провайдеров описаны в [source-api.md](source-api.md).
