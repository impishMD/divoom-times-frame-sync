# Режимы синхронизации альбома

Режим выбирается для команд `sync` и `run`. Он определяет, что делать с ранее отслеживаемыми фотографиями, которых больше нет в исходном альбоме или объединении источников целевого альбома. Способ хранения и автономного показа на рамке в обоих режимах одинаков.

Эти правила одинаково применяются к фотографиям и видео. Видео загружаются из Google Photos и Immich; тип записи не меняет правил владения, исключения из альбома и восстановления после перезапуска.

## Выбор режима

| Режим | Новые фото | Исчезнувшие фото | Старая версия изменённого фото |
| --- | --- | --- | --- |
| `mirror` | Добавить | Исключить из целевого альбома | Исключить после подтверждения новой версии |
| `append` | Добавить | Оставить | Оставить рядом с новой версией |

По умолчанию — `mirror`. Приоритет настроек:

1. `--sync-mode` в командной строке.
2. `SYNC_MODE` в окружении процесса.
3. `SYNC_MODE` из `.env` или файла, выбранного через `--env-file`.
4. Значение по умолчанию `mirror`.

Неизвестное значение даёт ошибку до выполнения синхронизации.

Разовая синхронизация с удалением исчезнувших фотографий:

```sh
.venv/bin/tfs sync --sync-mode mirror
```

Постоянная синхронизация в том же режиме:

```sh
.venv/bin/tfs run --sync-mode mirror
```

Только добавлять фотографии:

```sh
.venv/bin/tfs run --sync-mode append
```

Постоянная настройка в `.env`, в том числе для Docker Compose:

```dotenv
SYNC_MODE=mirror
SYNC_INTERVAL=300
```

После изменения `.env` перезапустите работающий процесс: настройки читаются при старте. Для уже созданного контейнера используйте `docker compose up -d --force-recreate`; при обновлении кода добавьте `--build`.

## Что означает удаление в `mirror`

Пример: Immich содержит A и B, а в целевом альбоме рамки есть загруженные сервисом A, B и вручную добавленная C. После исключения A из Immich следующий успешный цикл оставляет в целевом альбоме B и C. Для удаления достаточно убрать фото из исходного альбома; удалять оригинал из библиотеки Immich не требуется.

Применяется `Photo/RemovePhotoFromAlbum`: исключается связь фотографии с **целевым альбомом**. Файл остаётся в памяти рамки и может по-прежнему быть виден в «Все фото» или других альбомах. Это не очистка свободного места и не глобальное удаление через `Photo/DeletePhoto`.

Сервис удаляет только свои отслеживаемые записи. Перед удалением должны одновременно выполняться условия:

- В `device-state.json` совпадают устройство (`DeviceId`), ID целевого альбома и ID исходного альбома (для старой одиночной конфигурации) или стабильный ID группы назначения (для списка источников). Журнал также привязан к адресу и порту рамки.
- Запись известна локальному журналу: была импортирована или переиспользована после проверки её байтов.
- В свежей базе рамки ID и путь фотографии совпадают с записью журнала. Это защищает от удаления постороннего файла при повторном использовании числового ID.
- Фото ещё находится в целевом альбоме, но не входит в текущий объединённый набор подготовленных изображений.

Если два исходных фото дают одинаковые подготовленные WebP-байты, они представлены одной записью рамки. Она сохраняется, пока хотя бы одно из этих изображений остаётся хотя бы в одном источнике.

## Пустой альбом и ошибки

Успешно прочитанный **пустой** альбом является корректным состоянием. В `mirror` все отслеживаемые фото исключаются из целевого альбома; ручные фото остаются. В `append` фотографии и записи журнала сохраняются. При пустом наборе программа не переключает активный экран; вид пустого альбома определяется прошивкой.

Ошибка доступа к исходному сервису не равна пустому альбому. Сначала читается полный список и проверяются количества элементов. Превью скачиваются по одному только при необходимости загрузки на рамку. Если список получить не удалось, CLI не вызывает обновление рамки по старому манифесту. В штатном цикле удаления начинаются только после подтверждения всех текущих фотографий на рамке.

Изменения на рамке не являются общей транзакцией. Если несколько новых фото уже добавились, а следующая загрузка завершилась ошибкой, добавленные могут остаться, но удаление старых ещё не начинается. Если ошибка произошла при удалении одной из пачек, предыдущие пачки уже могли выполниться. Журнал сохраняет сведения для повторного цикла; программа заново читает базу и продолжает по фактическому состоянию.

Если несколько источников направлены в один альбом, ошибка чтения списка любого из них блокирует обновление всей этой цели до начала загрузок. Остальные целевые альбомы продолжают синхронизацию. Успешно прочитанный пустой источник убирается из объединения, но фото других источников остаются.

## Переключение между режимами

В `append` сервис продолжает учитывать оставленные фотографии в журнале. После перехода на `mirror` они будут исключены, если к этому времени всё ещё отсутствуют в Immich. Это работает и после перезапуска программы, и после нескольких циклов с пустым исходным альбомом.

В старой одиночной конфигурации смена устройства, исходного или целевого альбома меняет область журнала. В конфигурации `SOURCES_FILE` отдельный журнал хранится для каждого целевого альбома; изменение его состава источников меняет объединённый набор. Удаление секции источника в `mirror` может исключить его фото из общей цели; исчезнувшая из конфигурации целиком цель больше не обновляется. Полные правила — [sources.md](sources.md).

Если журнал (`data/device-state.json` в старой конфигурации или `data/targets/<hash>/device-state.json` для списка источников) утрачен, текущие изображения можно найти на рамке по именам и подтвердить по байтам. Для уже исчезнувших из Immich фото восстановить владение таким способом нельзя: сервис не удаляет их только по префиксу имени. Сохраняйте журнал между запусками и подключайте постоянный `./data:/app/data` в контейнере.

## Проверка работы

`status` показывает режим из конфигурации и число фотографий и видео в целевом альбоме, включая ручные. `sync --sync-mode mirror --dry-run` показывает статус с учётом выбранного режима, без записи на рамку. Это не список будущих удалений.

Пример лога завершённого цикла:

```text
Native album Photos (123456), mode=mirror: 2 photos and 1 videos verified, 0 downloaded, 0 uploaded, 1 removed, 0 missing items retained
```

`photos` и `videos verified` — число уникальных подготовленных фото и видео текущего объединения источников; `removed` — число записей, исключённых из целевого альбома; `missing items retained` — число отслеживаемых записей, оставленных режимом `append`, несмотря на их отсутствие в текущем наборе. Ручные фотографии в эти счётчики не входят.

Подробное описание команды удаления и её проверки: [frame-api.md](frame-api.md).
