# Проверка целостности и восстановление

[English](../en/repair.md) | **Русский**

## Обычная синхронизация и repair

`sync` и `run` сравнивают полные списки источников, сохранённые хеши медиа и базу рамки. После успешной проверки совпадение ID и пути записи, типа медиа, физического устройства, альбома и хешей позволяет использовать файл без скачивания из облака, конвертации и чтения содержимого с рамки. Новые загрузки и существующие файлы без подтверждённых записей проверяются по полному SHA-256 один раз. Поэтому первый цикл после обновления с 0.6.x однократно проверяет существующие медиа.

База рамки не содержит хешей и размеров файлов. Имя включает первые 24 hex-символа SHA-256 подготовленных байтов, но прошивка не меняет его при повреждении содержимого. Для обнаружения скрытого повреждения при сохранной записи в базе нужно полное чтение.

## Команды

Сначала остановите работающий сервис. `run`, `sync` и обе команды восстановления используют блокировку `DATA_DIR`. Они должны запускаться с одной конфигурацией и постоянным каталогом данных.

```sh
.venv/bin/tfs repair --dry-run
.venv/bin/tfs repair
```

Для Docker Compose:

```sh
docker compose stop
docker compose run --rm timesframesync repair --dry-run
docker compose run --rm timesframesync repair
docker compose up -d --no-build
```

`--dry-run` читает файлы целиком и показывает проблемы без загрузок, исключения связей и переключения показа. Локальные манифесты источников обновляются; при потере метаданных может потребоваться подготовка недостающих хешей. Журнал проверок не изменяется. Код завершения — 0 при отсутствии проблем, 1 при найденных повреждениях или ошибках.

`repair` проверяет все элементы, присутствующие в текущих списках настроенных источников. Сверяются полные SHA-256 фотографий, MP4 и обложек видео, проверяются типы записей, восстанавливаются отсутствующие файлы и связи с альбомами. Исправные файлы повторно не загружаются. Общий физический файл проверяется один раз за запуск. Результат содержит счётчики и проблемы/ошибки по элементам; незавершённое восстановление возвращает код 1.

Восстановление не исключает элементы, исчезнувшие из исходных альбомов, не меняет mirror/append и не включает показ. Посторонние файлы остаются нетронутыми. Ошибка чтения списка источника пропускает всю соответствующую цель; независимые цели могут обрабатываться дальше. Сетевой таймаут и HTTP-ошибка, кроме 404, означают неудачную проверку, а не доказанное повреждение.

## Замена и прерывания

Отсутствующая связь с альбомом восстанавливается с использованием проверенного файла. Для повреждённого или отсутствующего файла готовится замена из источника. Потеря хеша тоже может потребовать повторного скачивания и преобразования исходника. Другой видеокодер может создать другие байты — новый подтверждённый хеш сохраняется.

Сначала загружается отдельная копия. Если основное имя уже занято, замена получает имя `r<24 hex SHA-256><2 hex поколения>.webp` либо `.mp4`. Поколения начинаются с `00`, возрастают до `ff` и укладываются в ограничения длины имени прошивки. Обычная синхронизация и восстановление состояния предпочитают последнее поколение, но перед первым доверием всё равно проверяют полный хеш.

После проверки замены её связи добавляются во все затронутые обычные альбомы, включая альбомы вне конфигурации источников. Затем повреждённые записи исключаются из этих альбомов. **Старые повреждённые файлы остаются во «Все фото»: repair не удаляет файлы глобально и не освобождает память рамки.** Посторонние ручные фотографии сохраняются.

Перед загрузкой и изменением связей журнал сохраняет план замены, исходные записи и целевые связи. При прерывании сохраните `data/` и повторите `tfs repair`. Исправная уже загруженная замена используется повторно, перенос связей продолжается. Обычная синхронизация отказывается обновлять цель с незавершённым восстановлением. Неудачные промежуточные копии исключаются из альбомов вместе с исходной повреждённой записью после проверки исправной замены.

Если источник недоступен, выводится ошибка, существующие связи сохраняются. Если исходник незавершённой операции исчез или изменился либо перестали совпадать устройство/альбом, восстановление останавливается с явной ошибкой. Верните исходную конфигурацию или доступ к источнику и повторите команду. При необходимости ручного вмешательства сохраните резервную копию журнала.
