## Пропуск синхронизации при недоступной рамке

- Перед чтением исходных альбомов `sync` и каждый цикл `run` проверяют рамку запросом `Channel/GetClockInfo`, который только читает состояние. Таймауты соединения и чтения — по 3 секунды.
- При ошибке соединения или таймауте цикл пропускается без опроса источников, скачивания медиа и изменения локальных списков и журналов. `run` повторяет проверку после настроенного `SYNC_INTERVAL`.
- При потере связи сразу появляется одно предупреждение, затем напоминание не чаще раза в 10 минут. Подробности попыток остаются в DEBUG. Восстановление связи и результат следующего цикла выводятся автоматически.
- Сетевая ошибка во время синхронизации останавливает обработку остальных целей, сохраняя записанный прогресс. Вложенные таймеры больше не дублируют один сетевой сбой несколькими ERROR-сообщениями. К уже выполняющемуся запросу применяются обычные таймауты.
- Отказы API, ошибки HTTP и некорректный JSON остаются ошибками. Разовый `sync` при недоступной рамке возвращает ненулевой код завершения. Команда `cache` остаётся независимой от рамки.

```text
WARNING Frame unavailable; sync cycle skipped; retry in 30s; 3.0s
INFO Frame connection restored after 126.0s; resuming sync
INFO Sync cycle complete: 87 items, 0 uploaded, 0 removed; 2.0s
```

## Обновление

Сохраните конфигурацию и `data/`; миграция не нужна. Обновите образ до `v0.7.2` и перезапустите сервис или выполните sync в Argo CD. Для существующего Helm-чарта можно указать `image.tag: v0.7.2` в values.

Образы для `linux/amd64` и `linux/arm64` опубликованы в Docker Hub и GHCR:

```text
impishmd/divoom-times-frame-sync:v0.7.2
ghcr.io/impishmd/divoom-times-frame-sync:v0.7.2
```

Подробнее — в [руководстве по логам и доступности рамки](https://github.com/impishMD/divoom-times-frame-sync/blob/v0.7.2/docs/ru/sync-modes.md#проверка-работы).
