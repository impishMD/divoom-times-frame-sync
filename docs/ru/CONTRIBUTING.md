# Участие в разработке Divoom Times Frame Sync

[English](../../CONTRIBUTING.md) | **Русский**

## Среда разработки

Используйте Python 3.11+ на macOS или Linux. Для интеграционных тестов видео нужен FFmpeg 6+ с `ffprobe` и кодеком `libx264`. Если исполняемые файлы ffmpeg или ffprobe недоступны, эти тесты пропускаются. CI устанавливает FFmpeg.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -e '.[dev]' build
.venv/bin/python -m pytest -q
.venv/bin/python -m pip check
.venv/bin/python -m build
```

Тесты используют локальные HTTP-серверы и имитацию рамки, не обращаются к реальным альбомам и не требуют секретов. При изменении синхронизации проверяйте сохранность добавленных вручную элементов, частичные загрузки, перезапуск, потерю метаданных и очистку временных файлов.

## Структура проекта

Пути ниже указаны относительно `src/timesframesync/`:

- `providers/` — провайдеры публичных альбомов.
- `source.py` — контракт провайдера: полный `Album`, скачивание `preview()` и необязательная поддержка `download_video()`.
- `cache.py` — манифесты, подготовка временных медиафайлов и очистка.
- `video.py` — локальное преобразование FFmpeg, проверка длительности и создание обложки.
- `multi_sync.py` — объединение источников по альбомам назначения.
- `sync.py` — загрузка, проверка, журнал владения, режимы mirror/append.
- `frame.py` — локальный API Divoom.
- `cli.py` — команды `tfs` и `timesframesync`.

Провайдер должен отличать доступный пустой альбом от ошибки или неполного списка. ID и ревизии должны быть стабильными; временные CDN URL не должны входить в ключ кэша. Подробнее — в [руководстве по провайдерам](../sources.md) и [описании хранения](../storage.md).

## Подготовка изменений

Опишите проблему, итоговое поведение и выполненные проверки. При изменении пользовательского поведения или инструкций по установке обновляйте README на обоих языках. Поддерживайте соответствие английской и русской версий этого руководства и политики безопасности.

Используйте вымышленные данные в примерах и фикстурах. Не добавляйте реальные общие ссылки, токены, дампы устройства и личные фотографии в код, фикстуры, логи и сообщения о проблемах. `.env`, `sources.toml` и `data/` должны оставаться локальными. Об уязвимостях сообщайте по правилам [SECURITY.md](SECURITY.md).

Для сопровождающих: [руководство по выпуску релизов](../releases.md) описывает CI, публикацию образов для двух архитектур, секреты реестров и релизы по тегам (на английском).
