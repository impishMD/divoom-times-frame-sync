# Хранение и восстановление Divoom Times Frame Sync

[English](../en/storage.md) | **Русский**

## Рабочий цикл

1. Прочитать полный список каждого исходного альбома; проверить пагинацию и целостность ответа.
2. Атомарно обновить манифест источника. Для неизменённых ID и ревизий сохранить прежние контрольные суммы. Удалить неиспользуемые временные версии этого источника.
3. Для каждого целевого альбома прочитать базу рамки. Найти известные WebP и MP4 по имени, зависящему от SHA-256, и сверить содержимое.
4. Только для отсутствующих или новых фото скачать превью и подготовить временный JPEG 800×1280. Преобразовать его в WebP в памяти; сохранить контрольные суммы в манифесте. Для видео скачать файл воспроизведения, преобразовать в MP4 и создать обложку WebP.
5. Загрузить WebP либо MP4 с обложкой или использовать существующий совпадающий файл. Подтвердить содержимое и связь с целевым альбомом.
6. Атомарно сохранить владение записью в `device-state.json`, затем сразу удалить временный JPEG либо пару MP4/WebP. Перейти к следующему элементу.
7. После подтверждения всех текущих фото и видео применить политику `mirror`/`append` к исчезнувшим записям.

Обычный запуск не скачивает весь альбом заранее. Один процесс обрабатывает одно фото или видео за раз. Файлы от прежних неудачных попыток могут оставаться до успешной загрузки или изменения списка источника. Команда `tfs cache` — отдельный явный режим предварительного скачивания: он оставляет подготовленные фото и видео до синхронизации.

## Постоянные файлы

| Путь относительно `DATA_DIR` | Назначение |
| --- | --- |
| `sources/<id>/manifest.json` | Тип медиа, ID и ревизия источника, контрольные суммы подготовленных файлов, имя файла рамки |
| `sources/<id>/photos/*.jpg` | Временные изображения; удаляются после подтверждённого переноса |
| `sources/<id>/videos/*` | Временный исходник, MP4, обложка; подробности ниже |
| `targets/<hash>/manifest.json` | Объединённый текущий состав целевого альбома |
| `targets/<hash>/device-state.json` | Владение записями рамки, устройство, альбом, пути файлов |
| `device-state.json` | Предыдущий экран для `restore`; также журнал одиночного режима Immich |
| `manifest.json`, `photos/`, `videos/` | Манифест и временные медиафайлы одиночного режима Immich |
| `.lock` | Блокировка одновременного доступа нескольких процессов |
| `snapshot.webp` | Снимок экрана, созданный явной командой `snapshot` |

Прямые ссылки на изображения, подписи CDN, пароли и токены в манифесты не записываются. ID и названия альбомов являются личными данными; весь `DATA_DIR` исключается из публичного репозитория.

Нормальный повторный цикл сверяет свежий список источника и файлы на рамке. Отсутствие временного JPEG или MP4 само по себе не вызывает скачивание из облака. Для проверки SHA-256 файл рамки читается целиком по LAN, даже если он не изменился: на больших роликах и медленном Wi-Fi это может занимать заметное время. Байты проверки не сохраняются на диск. Постоянное место требуется для метаданных, а не для копий всей фототеки.

## Временные видеофайлы

Имена в `videos/` состоят из хеша ID альбома/элемента и ревизии преобразования. Расширения:

- `.download` — незавершённое скачивание; при обычной ошибке удаляется, при аварийном завершении перезаписывается в следующей попытке.
- `.source` — полностью скачанный ролик. Сохраняется при ошибке FFmpeg, чтобы не скачивать его заново. Удаляется после подготовки MP4 и обложки.
- `.part.mp4` — незавершённое преобразование, удаляется при обычной ошибке. Готовый результат атомарно переименовывается в `.mp4`.
- `.mp4`, `.webp` — готовое видео и обложка. Удаляются после проверки обоих файлов, флага видео в базе, членства в альбоме и записи журнала.

Пиковое место для одного видео — скачанный файл плюс преобразованный MP4 и обложка. Это временное место, а не постоянная копия альбома. Размер исходного видео не ограничивается размером экрана: при отсутствии перекодированной версии Immich возвращает оригинал. Google Photos отдаёт перекодированную версию для скачивания из публичного альбома. Скачивание, отправка на рамку и вычисление SHA-256 читают файлы частями.

## Ошибки и перезапуск

До подтверждения записи и сохранения журнала подготовленный локальный файл не удаляется. Обрыв загрузки, несовпадение прочитанных байтов, отсутствие связи с альбомом или ошибка записи журнала оставляют его для повторной попытки. Если процесс завершился после импорта, но до записи журнала, следующий запуск найдёт файл по контрольной сумме.

При ошибке загрузки новые уже добавленные фотографии могут остаться в целевом альбоме. Старые фотографии не исключаются, пока не подтверждён весь актуальный набор. Ошибка чтения любого исходного списка блокирует всю соответствующую цель до начала загрузок.

Нормальное удаление `mirror` меняет только членство в альбоме рамки и не освобождает её внутреннюю память. Это отдельная операция от очистки временных файлов на компьютере.

## Потеря состояния

Сохраняйте манифесты и журналы между запусками и резервируйте их вместе с конфигурацией. Если утерян только журнал, известные по манифесту контрольные суммы позволяют повторно найти текущие фото. Если утеряны и манифесты, фото и видео скачиваются и преобразуются заново; совпадение подготовленных байтов позволяет использовать прежний файл рамки.

В обоих случаях фотографии, уже исчезнувшие из источников, автоматически не удаляются: их принадлежность сервису больше неизвестна. Изменение настроек обработки или кодека может дать другие байты и отдельную копию визуально того же фото.

При переходе с версии с постоянным кэшем существующие JPEG используются для вычисления контрольных сумм и удаляются после подтверждения на рамке. Имена `im-<24 hex>.webp` сохранены для совместимости и предотвращения повторных загрузок.
