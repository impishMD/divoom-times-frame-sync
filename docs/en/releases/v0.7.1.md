## Quieter logs and detailed timings

- The default `INFO` level reports service startup/shutdown, the first successful cycle, and a single summary for cycles that upload, link, or remove media. Unchanged cycles produce a successful summary once every 10 minutes.
- `--log-level DEBUG` shows every cycle, each source and destination, and individual operations: downloads, conversion, uploads, photo/video and cover verification, frame API calls, local metadata, and temporary-file cleanup.
- Timings cover complete operations, including waiting and retries. The cycle duration excludes the pause between cycles. Long video operations also report their start and readback progress.
- Warnings, errors, and detected damage remain visible at the default level. One-shot commands retain completion summaries. A nonzero `linked` count identifies existing media added to a destination without another upload.

```sh
tfs run
tfs --log-level DEBUG run
```

See the [logging guide](https://github.com/impishMD/divoom-times-frame-sync/blob/v0.7.1/docs/en/sync-modes.md#checking-operation) for counter definitions and timing scopes.

## Upgrade

Keep configuration and `data/`, then restart the service after updating. Upgrading from v0.7.0 requires no metadata migration or additional media verification.

```sh
docker compose pull
docker compose up -d --no-build
```

If `TFS_IMAGE` is pinned, update it to `v0.7.1` first. Images for `linux/amd64` and `linux/arm64` are published with version and `latest` tags:

```text
impishmd/divoom-times-frame-sync:v0.7.1
ghcr.io/impishmd/divoom-times-frame-sync:v0.7.1
```

Source archives and Python packages are attached with SHA-256 checksums.
