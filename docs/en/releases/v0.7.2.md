# v0.7.2

**English** | [Русский](https://github.com/impishMD/divoom-times-frame-sync/blob/v0.7.2/docs/ru/releases/v0.7.2.md)

## Skip synchronization while the frame is offline

- Before listing source albums, `sync` and every `run` cycle check the frame with a read-only `Channel/GetClockInfo` request. Connection and read timeouts are 3 seconds each.
- If the connection fails or times out, the cycle is skipped without reading sources, downloading media, or modifying local manifests and journals. `run` retries after the configured `SYNC_INTERVAL`.
- An outage produces one warning immediately and at most one reminder every 10 minutes. Detailed attempts stay at DEBUG. Recovery and the next cycle result are reported automatically.
- A transport failure during synchronization stops remaining destinations, preserving recorded progress. Nested operation timers no longer duplicate the same connection failure as multiple ERROR messages. Existing timeouts still apply to a request already in progress.
- API rejections, HTTP errors, and invalid JSON remain errors. One-shot `sync` exits nonzero when the frame is unavailable. `cache` remains independent of the frame.

```text
WARNING Frame unavailable; sync cycle skipped; retry in 30s; 3.0s
INFO Frame connection restored after 126.0s; resuming sync
INFO Sync cycle complete: 87 items, 0 uploaded, 0 removed; 2.0s
```

## Upgrade

Keep your existing configuration and `data/`; no migration is needed. Update the image to `v0.7.2` and restart or sync the deployment. Helm users can set `image.tag: v0.7.2` in their existing chart values.

Images for `linux/amd64` and `linux/arm64` are published to Docker Hub and GHCR:

```text
impishmd/divoom-times-frame-sync:v0.7.2
ghcr.io/impishmd/divoom-times-frame-sync:v0.7.2
```

See the [logging and connectivity guide](https://github.com/impishMD/divoom-times-frame-sync/blob/v0.7.2/docs/en/sync-modes.md#checking-operation).
