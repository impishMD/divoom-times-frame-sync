## Google Photos video sync

Videos in public Google Photos albums now sync to native Divoom Times Frame albums alongside photos. Existing Google Photos source configurations work without changes or a Google account login.

- Downloads the video supplied by Google's public album viewer in chunks, then prepares an 800×1280 H.264/AAC MP4 and a WebP cover for autonomous playback.
- Uses the same mirror/append rules, upload verification, persistent sync journal, and temporary file cleanup as Immich videos.
- Reuses unchanged videos across sync cycles, including when Google's temporary download URL changes.
- Rejects incomplete downloads, thumbnail/HTML responses, and redirects outside Google's media CDN. Failed or still-processing videos are retried without pruning existing album items.
- GitHub release titles now contain only the version.

Photo support remains available for Google Photos, iCloud Photos, Immich, OneDrive, and Yandex Disk. Video support is available for Google Photos and Immich.

## Update

```sh
docker compose pull
docker compose up -d --no-build
```

If `TFS_IMAGE` is pinned in `.env`, update its version to `v0.5.0` before pulling. Keep the existing `data/` directory and configuration.

Images for `linux/amd64` and `linux/arm64`:

```text
impishmd/divoom-times-frame-sync:v0.5.0
ghcr.io/impishmd/divoom-times-frame-sync:v0.5.0
```

Source archives and Python packages are attached with SHA-256 checksums. `container-digests.txt` records the immutable image references. See the [English README](https://github.com/impishMD/divoom-times-frame-sync/blob/v0.5.0/README.md) or [Russian README](https://github.com/impishMD/divoom-times-frame-sync/blob/v0.5.0/README.ru.md) for configuration and playback settings.
