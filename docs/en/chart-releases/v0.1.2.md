# Helm chart 0.1.2

**English** | [Русский](https://github.com/impishMD/divoom-times-frame-sync/blob/chart-v0.1.2/docs/ru/chart-releases/v0.1.2.md)

Adds optional PVC permission preparation for storage drivers that leave volumes owned by root, and for imported data owned by another user. This addresses startup failures such as `Permission denied: '/app/data/.lock'`.

```yaml
volumePermissions:
  enabled: true
```

The option is disabled by default. When enabled, an init container runs as root before the worker, recursively assigns the data volume to the worker's UID/GID, and grants owner read/write and directory access. It uses the application's image, mounts only the data PVC, and receives no source credentials. The worker continues to run without root. Existing file contents are preserved; the namespace must allow the init container's root user and required capabilities.

For Argo CD, set the chart source's `targetRevision` to `0.1.2`, add the value above, and sync. Existing PVCs and Secrets can be reused. The application image remains **0.7.1**.

See the [Helm and Argo CD guide](https://github.com/impishMD/divoom-times-frame-sync/blob/chart-v0.1.2/docs/en/helm.md) for permissions and the Synology iSCSI case. Chart checks cover both the default configuration and recovery of a root-owned volume with existing private files while `fsGroup` is disabled.
